# English Coach PWA — Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the Phase 1 privacy bug, make bubbles land faster and the live line visible, let the learner choose the AI provider for each job (Groq, OpenAI/ChatGPT, Google Gemini, Anthropic Claude, a local OpenAI-compatible server) with their own key, and add the coach: the «Respuesta» button, curated phrases, notes, profile and context, and the closing report.

**Architecture:** One pure `providers.js` table describes every provider and builds/parses its requests for two jobs — `transcribe` (audio → text) and `chat` (system + user → text). `transcribe.js`, `translate.js` and the coach call through it, so a provider is one table entry. The coach (`coach.js`, `phrasebook.js`) is copied from the extension and its network layer is replaced by `providers.js`. Latency drops by sending each segment to transcription in parallel with its voice embedding. The live line gets an install button for Chrome's on-device speech pack and, where that does not exist, a local Whisper preview lane (desktop with WebGPU).

**Tech Stack:** as Phase 1 — plain ES modules, no build step, no dependencies; Node for tests; Chrome over CDP for the e2e harness.

**Spec:** the user's requests on 2026-10-02 ("deja abierto para cualquier IA… que pueda seleccionar entre chatgpt, gemini, groq, claude etc y su apikey") and 2026-10-09 (after the first real test: "me reconoció muy bien la voz… pero la transcripción es lenta, no la veo en vivo; tampoco tengo el botón de ayuda para generar una respuesta automática"), the in-chat design approved by "continúa con la tarea… completa la fase 2", and `docs/2026-09-29-plan.md` §3 (Phase 2: «Frases, notas, respuesta sugerida e informe, reutilizando coach.js y phrasebook.js»).

## Global Constraints

All of Phase 1's (see `CLAUDE.md`), plus:

- Every provider key is stored only in IndexedDB on the device, one per provider; a key is sent only to its own provider's host, never in a URL or query string (Gemini uses the `x-goog-api-key` header), never logged; every error body is redacted.
- The CSP `connect-src` lists exactly the provider hosts in `providers.js` plus `http://localhost:*` and `http://127.0.0.1:*` for the local provider; no wildcard scheme (`https:`) — a custom endpoint is local-only by design, so audio can never be sent to an arbitrary host.
- Claude has no audio input: it is offered for `chat` only, and the UI says why it is absent from transcription.
- The privacy screen and settings state, for the current choice, which provider receives the audio and which receives text.
- Nothing in the test harness reaches a real external API except the model download hosts; the Groq stand-in grows OpenAI-, Gemini- and Anthropic-shaped endpoints.
- Copied files are recorded in `docs/ORIGIN.md` with their source commit (`ded2c34` in `/Users/octopus/Downloads/english-coach`, which is never modified).
- Measure, then quote numbers: latency and live-line changes are measured with `node e2e/run.mjs` before and after.
- Commit messages: subject, blank line, `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Implementers never dispatch subagents.

### Task 2: Transcribe in parallel with the voice print

**Files:** `session.js`, `session.test.js`.

Today each segment waits for its embedding (plus the window scan for ≥ 3 s segments) before its upload starts. Start the upload as soon as the segment arrives; the label path runs concurrently; the bubble is emitted when both are done, still in capture order. The 5b split still decides the parts: when a scan splits a segment, the parts' uploads replace the whole-segment upload (abort it if it is still in flight; if it already finished, re-upload the parts — measure how often that happens and report it).

- [ ] Tests with fake embed/transcribe delays: total time ≈ max(embed, transcribe), not the sum; order preserved; a split replaces the whole-segment result; failures on either path still emit an error and let the next segment through.
- [ ] Measure with `node e2e/run.mjs paulina samantha --condition=room` before and after (latency p50/p90 and accuracy), normal and `--throttle`. Paste both.
- [ ] Gate, commit `perf(session): transcribe while the voice print is computed`.

### Task 3: `providers.js` — any AI, its own key

**Files:** Create `providers.js`, `providers.test.js`; modify `transcribe.js`, `translate.js`, `index.html` (CSP), `ui/settings.js`, `ui/consent.js`, `store.js` (settings shape + migration), `e2e/mock-groq.mjs` (→ also serves the new shapes), `e2e/harness.mjs`, `CLAUDE.md`, `README.md`.

**Interfaces (produced):**
- `PROVIDERS`: `{ id, label, jobs: ['transcribe'|'chat'], base, keyHeader, models: { transcribe?, chat? } }` for `groq`, `openai`, `gemini`, `anthropic` (chat only), `local` (OpenAI-compatible, base editable, `http://localhost:*` / `http://127.0.0.1:*` only).
- `buildTranscribe(providerId, { audioWav, model, lang, base })` → `{ url, init }` and `parseTranscribe(providerId, json)` → `{ text, lang }`.
- `buildChat(providerId, { system, user, model, maxTokens, schema, base })` → `{ url, init }` and `parseChat(providerId, json)` → `text`.
- `async callTranscribe(settings, samples, { signal })`, `async callChat(settings, { system, user, maxTokens, schema, signal })` — pick the provider and key from settings, add the auth header, fetch with timeout and the Phase 1 retry policy, redact errors, stage them (`[transcripción]`, `[coach]`, `[traducción]`).
- Settings: `{ transcribeProvider, chatProvider, keys: { groq, openai, gemini, anthropic, local }, models: { <id>: { transcribe, chat } }, localBase }`; the Phase 1 `groqKey`/`groqBase` migrate into it (`groqBase` stays as the harness override).

Request shapes to implement (verify each against the provider's current public API docs before coding, and cite the doc URL in a comment):
- Groq / OpenAI / local transcription: `POST {base}/v1/audio/transcriptions` (Groq: `/openai/v1/…`), multipart `file`, `model`, optional `language`, `response_format` (`verbose_json` in bilingual mode); `Authorization: Bearer`.
- Gemini transcription: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, `x-goog-api-key`, body with `inline_data` (`audio/wav`, base64) + a short instruction "Transcribe this audio verbatim; reply with the transcript only"; language detection reported as null unless the response states it.
- Chat: OpenAI-compatible `/chat/completions` (Groq, OpenAI, local); Anthropic `POST /v1/messages` with `x-api-key`, `anthropic-version`, and `anthropic-dangerous-direct-browser-access: true`; Gemini `generateContent` with `systemInstruction`.
- Defaults (editable per provider in settings): transcription Groq `whisper-large-v3-turbo`, OpenAI `gpt-4o-mini-transcribe`, Gemini `gemini-2.5-flash`; chat Groq `openai/gpt-oss-120b`, OpenAI `gpt-4.1-mini`, Gemini `gemini-2.5-flash`, Anthropic `claude-haiku-4-5-20251001`. Check each still exists in the provider's docs; if one does not, pick the provider's documented equivalent and say so.

- [ ] Tests per adapter with a stubbed `fetch`: URL, headers (the key only in its header), body shape, response parsing, error redaction, a key never appearing in a thrown message; Claude refused for `transcribe`; `local` refuses non-localhost bases.
- [ ] Settings UI: «Transcripción» and «Traducción y coach» pickers, one key field per provider shown only when chosen, model fields with the defaults as placeholders, a one-line note under Claude ("Claude no recibe audio: úsalo para la traducción y el coach").
- [ ] Consent/privacy text reflects the current choice.
- [ ] Harness: the stand-in answers the OpenAI, Gemini and Anthropic shapes; `e2e/run.mjs --transcribe=<id> --chat=<id>`; run once per transcription provider (groq, openai, gemini) against the stand-in and paste totals.
- [ ] Gate, commit(s) `feat(providers): choose the AI and key for transcription and for chat`.
